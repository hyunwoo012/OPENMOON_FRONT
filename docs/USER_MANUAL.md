# OPENMOON AI 사용자 매뉴얼

## 1. 시스템 목적

OPENMOON AI는 열린문디자인의 견적 업무를 보조하는 로컬 업무 시스템이다.

주요 업무 흐름은 다음과 같다.

```text
메일 수신/가져오기
→ AI 메일 분석
→ 고객/품목/규격 확인
→ 과거 견적 및 단가 근거 확인
→ 담당자 수정 및 승인
→ 내부 견적 XLSX 생성
→ 고객용 PDF 생성
→ 메일 제목 검토
→ 담당자 선택
→ 승인 및 고객 답장 발송
```

중요한 원칙은 **AI가 견적을 임의로 확정하지 않고 담당자가 최종 확인한 뒤 발송하는 것**이다.

---

## 2. 권장 실행 환경

- Windows 11
- Python 3.11
- Node.js 20 이상
- Microsoft Excel
  - 일반 메일 분석과 화면 사용에는 없어도 됨
  - 기존 복합 Excel 파일에 시트를 추가하거나 고객용 PDF를 생성하려면 필요
- 인터넷 연결
  - Daum 메일 동기화
  - OpenAI API 분석 사용 시 필요

---

## 3. 최초 설치

프로젝트 폴더:

```text
C:\Users\<사용자>\OPENMOON_FRONT
```

프로젝트 루트에서 실행한다.

```bat
setup.bat
```

`setup.bat`은 다음 작업을 수행한다.

1. `.venv` Python 가상환경 생성
2. Python 패키지 설치
3. `.env`가 없으면 `.env.example` 복사
4. 프론트엔드 패키지 설치
5. 프론트엔드 빌드
6. 데이터베이스 초기화

설치가 끝나면 `.env`를 확인한다.

---

## 4. 환경설정

주요 환경변수:

```env
DAUM_LOGIN_ID=
DAUM_APP_PASSWORD=
OPENAI_API_KEY=
ALLOW_LIVE_SEND=false
```

### DAUM_LOGIN_ID / DAUM_APP_PASSWORD

메일 동기화와 실제 발송에 사용한다.

### OPENAI_API_KEY

AI 메일 분석과 이미지 첨부 분석에 사용한다.

API 키가 없으면 일부 규칙 기반 기능은 사용할 수 있지만 이미지 Vision 분석 등은 제한된다.

### ALLOW_LIVE_SEND

```env
ALLOW_LIVE_SEND=false
```

이면 실제 고객 메일 발송을 차단한다.

실제 발송 테스트까지 모두 끝난 후에만:

```env
ALLOW_LIVE_SEND=true
```

로 변경한다.

## 5. 프로그램 실행

프로젝트 루트에서:


```text

```

다음 오류가 나타날 수 있다.

```text

```


# 6. 화면 구성

## 6.1 이메일

주요 업무 화면이다.

화면은 다음 패널로 구성된다.

- 메일 목록
- 원본 메일
- AI 분석/최종 검토
- Agent
- 하단 과거 견적/가격 근거

패널은 폭을 조절할 수 있고 순서를 변경하거나 접을 수 있다.

화면 배치는 브라우저 로컬 저장소에 보존된다.

화면이 이상하게 배치된 경우 `화면 초기화` 기능으로 기본 배치로 되돌릴 수 있다.

---

## 6.2 검토 필요

AI가 자동 처리하기 어렵다고 판단한 메일을 확인하는 화면이다.

예:

- 품목이 불명확함
- 수량이 없음
- 가격 근거가 부족함
- 첨부파일에서 필요한 정보를 확인하지 못함
- 고객 요청이 모호함

현재 시스템은 모든 품목에 동일한 고정 규격을 요구하지 않는다.

**품목별 제품 카탈로그에 정의된 규격을 기준으로 입력한다.**

---

## 6.3 견적서

# 7. 메일 가져오기

## 7.1 Daum 메일 동기화

상단의 `메일 동기화` 버튼을 누른다.

시스템은 Daum 받은편지함을 확인하여 새 메일을 로컬 DB로 가져온다.

이미 가져온 IMAP UID는 중복으로 생성하지 않는다.

---

## 7.2 EML 직접 가져오기

`EML 가져오기`를 선택하여 `.eml` 파일을 직접 등록할 수 있다.

테스트 메일이나 전달받은 메일 파일을 확인할 때 사용한다.

---

# 8. 메일 삭제

메일 목록의 휴지통 버튼을 누르면 프로그램 목록에서 메일을 삭제할 수 있다.

중요:

- 실제 Daum 받은편지함의 메일은 삭제하지 않는다.
- 로컬 DB에서도 행 자체를 완전히 제거하지 않는다.
- `deleted_at`을 기록하는 soft delete 방식이다.
- 삭제한 IMAP UID는 DB에 유지되므로 다음 동기화 때 같은 메일이 다시 나타나지 않는다.

즉:

```text
OPENMOON 화면에서는 삭제
Daum 원본 메일은 보존
재동기화해도 다시 표시되지 않음
```

## 9.1 개별 분석

메일을 선택하고 `분석` 버튼을 누른다.

AI가 다음 내용을 추출한다.

- 고객 정보

- 품목

- 일정
- 기타 요청사항

- 분석 요약 및 판단 근거

---

## 9.2 전체 분석

메일 목록의 `전체 분석`을 누르면 `NEW` 상태의 메일을 순차적으로 분석한다.

처리 중에는 버튼이 `분석 중지`로 변경된다.

중지를 누르면 현재 처리 중인 메일은 마무리한 뒤 다음 메일부터 중단한다.

# 11. 품목 입력

제품 카탈로그:

```text
config\product_catalog.json
```

현재 카탈로그에는 인쇄물, 광고물, 디자인물 제품이 등록되어 있다.

`+ 품목 추가`를 누르면 제품 검색/선택창이 열린다.

등록된 품목이 없으면 직접 입력도 가능하다.

제품마다 필요한 입력 항목이 다르다.

예:

### 명함

- 사이즈
- 용지
- 수량
- 인쇄도수
- 후가공
- 납품여부

### 현수막

- 용도

각 선택 항목은 기본 선택지뿐 아니라 직접 입력도 가능하다.

## 11.2 제작 원가

각 품목 하단에 `제작 원가(원)`을 입력할 수 있다.

제작 원가는:

- 내부 관리 정보
- 고객 판매 단가와 별도
- 고객 견적 합계 계산에 포함되지 않음
- 고객용 PDF에 노출되면 안 됨

---

## 11.3 품목 삭제

품목 우측 삭제 버튼을 누르면 해당 품목을 제거할 수 있다.

수정 후 반드시 `수정 저장`을 눌러 현재 품목 목록을 저장한다.

# 12. 가격 및 과거 견적 확인

하단 영역에서 다음 정보를 확인할 수 있다.

- 동일 회사 과거 견적
- 동일 고객 과거 견적

# 13. Agent 사용

Agent에서는 현재 선택된 메일을 기준으로 다음 작업을 수행할 수 있다.

예:

```text
이 고객의 과거 현수막 견적 보여줘
```

Agent는 다음 자료를 참조할 수 있다.

- 현재 메일
- 현재 견적 정보
- 과거 견적
- 가격표
- 회사 지식
- 장기기억

Agent가 변경 작업을 수행한 경우 화면의 실제 값이 변경됐는지 확인한다.

# 14. 견적서 생성

`견적서 생성`을 누르면 저장 방식을 선택한다.

선택 가능 방식:

1. 기존 견적 Excel에 새 시트 추가
2. 부서 공용 파일
3. 담당자별 파일
4. 별도 새 견적 파일

내부 Excel에는 회사 업무용 정보가 보존된다.

---

# 15. Microsoft Excel이 필요한 기능

일반적인 UI, 메일 분석, DB 기능은 Microsoft Excel 없이도 사용할 수 있다.

다음 기능 중 **일부 기존 복합 XLSX 파일에 견적 시트를 직접 추가하는 기능**은 Windows Excel COM 자동화를 사용한다.

고객용 PDF는 다음처럼 동작한다.

- Excel 사용 가능: 기존 Excel 견적 시트를 기준으로 PDF 변환
- Excel 없음/COM 오류: Python이 고객용 PDF를 직접 생성하여 브라우저에서 열 수 있음

따라서 Excel이 없는 PC에서도 `별도 견적 파일` 방식으로 견적을 생성하고 고객용 PDF를 확인할 수 있다.

기존 복합 XLSX 처리 중 Excel이 없거나 COM 등록이 되어 있지 않으면 다음과 같은 오류가 발생할 수 있다.

```text
REGDB_E_CLASSNOTREG
New-Object -ComObject Excel.Application
```

이 경우 `별도 견적 파일` 방식으로 테스트하거나, 기존 복합 XLSX에 직접 시트를 추가해야 하는 최종 운영 검증은 Microsoft Excel이 정상 설치된 Windows PC에서 수행한다.

---

# 16. 내부 XLSX와 고객용 PDF

시스템은 두 파일의 목적을 분리한다.

## 내부 XLSX

회사 내부 업무용이다.

- 내부 견적 관리
- 제작 원가 등 내부 정보 보존 가능

## 고객용 PDF

고객 발송 전용이다.

고객 PDF 생성 시 다음 정보는 제거한다.

- 내부 담당자 관련 셀
- 전화번호
- 이메일
- 제작 원가
- 내부 식별값

또한 고객에게 표시되는 품목명은 가능한 경우 대표 품목명으로 정리한다.

예:

```text
친환경 현수막
→ 현수막
```

---

# 17. 발송 제목 수정

견적서 화면에서 고객에게 보낼 제목을 선택하거나 직접 수정할 수 있다.

기본 예:

```text
[열린문디자인] 요청하신 견적서를 보내드립니다 - 고객명
```

사용 방법:

1. 제목 예시 선택 또는 직접 입력
2. `제목 저장`
3. 담당 직원 선택
4. `승인 및 답장`

`제목 저장`을 누르지 않고 바로 승인하더라도 현재 입력된 제목을 먼저 저장하도록 구성되어 있다.

이미 `SENT` 상태인 견적의 제목은 수정할 수 없다.

---

# 18. 승인 및 메일 발송

발송 전 확인:

- 고객 이메일 주소
- 견적 금액
- 품목 및 규격
- 발송 제목
- 담당 직원
- 고객용 PDF
- `ALLOW_LIVE_SEND=true`

발송 시 고객에게는 **내부 XLSX가 아니라 고객용 PDF만 첨부**한다.

고객용 PDF가 없으면 발송을 차단한다.

또한 PDF가:

- 실제 PDF 형식인지
- 현재 내부 XLSX보다 오래된 파일은 아닌지

확인한 뒤 발송한다.

직원별 메일 서명은 기존 서명 이미지를 사용한다.

---

# 19. 메일 발송 실패 시

발송 상태가 `FAILED`라면 무조건 즉시 재발송하지 않는다.

먼저 실제 고객 수신함 또는 회사 보낸메일함을 확인한다.

SMTP 응답 전에 연결이 종료된 경우 실제로는 전송됐는데 프로그램만 실패로 판단했을 가능성이 있기 때문이다.

확인 후 필요한 경우에만 `발송 재시도`를 사용한다.

# 22. 자주 발생하는 오류

## `No module named pytest`

가상환경이 활성화되지 않은 경우가 많다.
